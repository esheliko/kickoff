# kickoff: project templates

A GitHub repo that creates new projects. A project is composed from **layers**, later layers overwrite earlier files:
1. `kit/core/`: the work model every project gets (standing rules in `process/rules.json`, hooks, `/process` skill, CI-status scripts, their tests, issue template).
2. `templates/<name>/`: one technology stack, with `template.json` (manifest), `{{PLACEHOLDERS}}`, its own `scripts/bootstrap.mjs`. Have: `web-app` (Next.js + Supabase + Vercel), `cross-platform-app` (Rust engine -> WASM + native, React UI, Tauri shells, Vercel static).
3. `seeds/<name>/` (optional): project-specific starter content on a template (docs, extra modules); `seed.json`, `CLAUDE.seed.md`. Have: `overcut`.
Other: `kit/lib/` (compose + shared bootstrap helpers, tested in `kit/tests/`), `kit/snippets/` (CLAUDE.md sections shared via `<!-- kit:include name -->`), `.github/workflows/new-project.yml` (creates a project, no manual steps; inputs `template`, optional `seed`), `.claude/skills/new-project/` (how a session runs it), `tools/` (local checks).
- Rule text that differs per stack uses `<<VAR>>` in `kit/core/process/rules.json`; every template supplies the values in `template.json` `ruleVars` (a test fails if one is missing). Do not put stack words into kit/core.
- Add a template: new folder under `templates/` with `template.json` (`templateOnly`, `board`, `verify`, `ruleVars`), `CLAUDE.md` containing the `<!-- rules:begin/end -->` markers, and `scripts/bootstrap.mjs` (use `kit/lib/github.mjs`; takes `--template-dir --name --slug --purpose --visibility [--seed] [--dry-run]`). Prove it: `node tools/check-template.mjs <template> <out-dir> --build` (compose + install, lint, typecheck, test, build), plus `npm test` here.
- Add a seed: `seeds/<name>/` with `seed.json` (`template`, `name`, `purpose`); files overlay the template. Try: `node tools/instantiate-local.mjs <template> <out> --seed <name>`.
- Changes go through a branch + PR. Never commit secrets. `kit/core` process files and the `web-app` process behaviour came from the Typecast repo (`docs/project-kit/tools/build-kit.mjs --out`): move/parameterize them here only to keep stacks reusable, and keep web-app output unchanged (compare composed output before/after).
- **Projects the kit created are yours to keep working.** The kickoff session that creates a project stays responsible for it: the child session brief names it as parent so the child can `send_message` it, and when a child reports a problem (CI, process files, hooks, settings) fix it in the project, unblock the child, and fix the kit cause with a test. Details: `.claude/skills/new-project/SKILL.md`. After creating a project, verify it (commit on `main`, first `verify` run has jobs), do not trust a green workflow run.
